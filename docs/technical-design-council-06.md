## 0. 位置付けと判断原則
- UI Labは本体v0.10と独立した操作・視覚設計用の試作品。通常UIをユーザーが繰り返し試用し改善した。正式な製品の精度・性能・機能完成を意味しない。
- 現在のUIを次段階の基準とする。後続実装でフレームワーク・描画方式を変更しても、操作の意味・直接操作・視認性を維持する。UI UX Pro Max・21st.devは設計の参考として要望されたが、採用や適用完了は未検証。単に利用するためのフレームワーク移行は行わない。
- 目的は未来の風景を発見し撮影に出かけたくなる体験。技術情報を見せること自体を目的にしない。ボタンを増やさず、必要な情報だけ独立レイヤーで表示する。
- 地形・天体・光・気象・検索は第1〜5回設計に従う。数値の精度、予報信頼性、欠損、取得待ちを隠さない。
- この文書では合意したUI動作、試作実装上の暫定値、将来要件を区別する。正式アイコン画像は以前の選択を維持し、今回変更したのはヘッダー文字のみ。

## 1. 共通画面構成
| 項目 | スマートフォン縦画面 | PC・横画面 |
|---|---|---|
| ヘッダー | RidgeArc、探索、設定（アイコン） | RidgeArc、探索、撮影情報、設定 |
| メイン | 地図上・稜線下、両方が初期状態 | 地図左・稜線右、初期40:60 |
| 切替 | 左の画面は稜線のみ、中央は両方、右は地図のみ。矢印で切替 | 2画面を維持、境界を直接ドラッグ |
| 時間操作 | 下部マルチトラック | 同じ |
| 詳細情報 | 下端「撮影情報・イベント」 | 右上情報ボタン |
| 旧下部ナビ | 廃止 | 廃止 |

- スマホは地図・稜線の要素を再作成しない。約170msの分割遷移、Leaflet invalidateSize、地図中心・ズームを保持する設計。両画面から地図のみへ進む矢印は地図側の高さ25%付近、稜線のみへは83%付近。戻り矢印も対応。分割は縦50:50を初期値とする。
- PC境界は20:80〜80:20（暫定制限）。ドラッグ、キーボード左右で変更し、両方の画面を残す。地図中心を維持する設計。スマホ横画面もPC系レイアウトとなる現在のCSS条件は実機確認が必要。
- 設定と探索はヘッダー直下に表示。PC右寄せ、スマホ全幅。タイムライン固有メニューだけ下部。外側クリック/タップ、閉じる、Escで閉じ、背面操作にイベントを通さない。
- 詳細情報は専用画面へ移行し、上部固定戻る操作と下部戻る操作。約180msの入退場、reduced-motion対応。PCも詳細画面を共用。
- 色調は暗いスレート系背景と落ち着いた金色を基本にする。地図は低彩度。ロゴ・画像資産の再生成は不要。
- 稜線輪郭ON時、ヘッダーのRidgeのみ白塗り＋赤縁取り、Arcは通常文字。OFFで通常文字に戻る。現在の実装は0.85px #f16b70、白 #fff。状態表示であり画像ロゴを変更しない。

## 2. 地図と観測地点
- 地理院標準地図、観測ピンのドラッグと地図クリックで地点変更。地図のパン・ズームは通常操作。地図上の縮尺や地名・道路の判読性を維持。試作にLeafletズームコントロールあり（過去の「ズームボタン廃止」はタイムライン等のボタンであり、地図の現行表示を確認して判断する）。
- 画角を金色の扇形で表す。辺をドラッグすると観測方向を回転、左右の辺を2指で同時操作すると画角・方向を調整。同じ辺の2指は回転。辺の透明ヒット幅26px、通常の地図操作と競合しないようにする。扇形描画は模式的な長さ/平面近似で、測地的に厳密な画角範囲ではない。
- 地表標高（裸地DEM）、地上高（カメラ高さ）、視点標高（前二者の和）を地図上に表示。地上高0〜300m、0.1m刻み、初期1.6m（現行本体と共通）。地表と視点の基準を混同しない。地上高変更で本体の地形・遮蔽・可視域を再計算する必要がある。
- v0.20から標高タイルの取得コードを接続。1m→5m A/B/C→10mの順で、本体core.mjsのelevationStencil/interpolatedHeight/decodeElevationを共用。地点変更を180msデバウンス、旧取得を取消、欠損時未取得表示。通信・ブラウザ互換性・地図との実測整合は未確認。
- 地平線円と外側減光（27%）は独立レイヤー、既定ON。取得済み視点標高hを球面地球半径Rに用い、地表弧長 R acos(R/(R+h)) を半径とする。大気差なし・海面基準の幾何学的参考値。未取得時の32km円は「模式」と表示する暫定代替で、製品では実値と誤認させない。円外の高い山は可視になり得る。
- 地平線円、実地形可視域、被写体日照影は別の量・別レイヤー。未知と不可視を区別する。

### 2.1 地図側の追加仕様（採用、未実装）
製品構想5.1.3も参照。実装時期・探索UIは未決定。
1. 実可視領域（viewshed）：視点高と地形による可視・不可視・未判定を表示。
2. 日照・陰影：時間変更に伴う地表・山腹の直射光と影の変化。
3. 逆可視域：被写体・山頂を指定し、観測可能な地点を表示。
4. 撮影適地のヒートマップ：可視性、構図、光、遮蔽、気象等を条件として、候補地点/日時と根拠を示す。
5. 太陽/月の時刻別方位線：地図で天体方位の変化を確認。方位のみで重なりや可視性を断定しない。
6. 地形断面：任意2点間の標高・視線・遮蔽の位置を確認。
7. 地図と稜線の双方向選択：山頂・地形点を相互にハイライト。位置/距離/山名同定の不確実性を扱う。

## 3. 稜線・天体画面
- 2Dパノラマの風景を基本。複数の稜線と距離色、陰影、太陽/月の実視直径、軌跡を共通角度座標に投影。描画方式は第1〜5回の技術設計を参照。試作の5層合成波形は実地形ではない。
- ドラッグで観測方向、ピンチ/ホイールで画角（現行5〜180°）。日時変更で構図を勝手に変えない。上下方向・天頂は本体で対応する仕様で、UI Labは水平方向のみ。
- 太陽・軌跡の時刻ラベル。太陽本体を直接ドラッグして軌道に沿って時刻変更。軌跡タップで移動。遮蔽中の太陽円盤・軌跡は破線で別レイヤー表示（円盤の可視領域計算は未実装）。
- 太陽ダブルタップで拡大ルーペON/OFF。閉じる操作あり。ズームして十分に拡大されたら自動非表示、戻すと再表示。画角42°閾値は暫定。ルーペは小さめ、2画面時さらに縮小し、一般設定で2画面時表示を切替。太陽とラベルを覆わないよう4隅から選択し、安易に角を変えず、衝突時のみ移動、候補がなければ隠す。画面の拡大を切り抜く方式は試作のみ。
- 山名と標高は山頂から斜め上に伸びるリーダー線に沿わせる（現在60°）。模式ピーク1点。製品では実際の山頂同定、遮蔽、ラベル重なり・選択、距離を扱い、未知の山名や標高を捏造しない。
- 高度0°基準線は山の後ろでも薄い破線で表示。実水平線の伏角、大気差、地形地平線と区別。試作の位置はh×0.66の模式値。
- 従来の立体コンパスは廃止。稜線画面下端の方位目盛り（高さ25px暫定）、中央金色マーカー、画角に応じた目盛り間隔、N/E/S/Wを含む度数表示。非表示可。0/360°を跨ぐ表示に対応。
- 高仰角/天頂付近の方位角の特異性：共通の天球座標線（方位線と高度線）を投影し、天頂付近で収束/放射状になる表示を検討する。天頂そのものの方位は一意でない。下端目盛りが誤認を生む投影では消す等の設計が必要。現状未実装。

## 4. タイムラインと日時操作
- PC/スマホ共通の連続時間軸（JST）。時間軸は左右に動かし、選択縦線は中央に固定、幅2px。日付の強調帯は不要。PCでもクリック位置にヘッドを移動させない。
- ピンチ/ホイールで表示幅を連続変更、1分〜366日（暫定）。刻みは表示幅に自動連動。通常目盛り23px、タップで72pxに展開して期間移動、再タップで戻す。
- 日付入力を時刻左側に配置。期間設定には開始日・終了日、トラックON/OFF、時刻固定。プリセットと適用ボタンは廃止、自動反映。終了日は包含、内部rangeHiは翌日排他的。最大366日。通常トラックは設定範囲内。展開目盛りで期間外へ移動すると範囲拡張。ズームアウトによる自動範囲拡張は現行試作上の判断で、製品採用前に再検討。
- 時刻固定既定ON。時刻表示のタップ/クリックで切替、赤枠はON状態。時刻文字の左右ドラッグで微調整し固定トグルと区別（5px移動閾値）。キーボードEnter/Space切替、左右微調整。期間移動時に時刻を維持し、細かい時刻スケールでは連続移動。通常の目盛りドラッグは日内時刻の微調整。
- 重要な未解決事項：広域スケールの固定時刻モードは、現在のscrollPreviewと日付セル選択により、中央線は日付を示すが、線の下の連続時間座標と実選択時刻が一致しない場合がある。選択時刻・バー・目盛りの意味を一致させる仕様を実データ統合時に確定し、回避目的でヘッドや帯を動かさない。展開目盛りの期間移動と固定時刻の整合も検証する。
- トラックは現象ごとの色付き区間、名称はバー内部の可視部分に置く。狭い場合は左側にフォールバック。画面右端は「開始 時刻」「終了 時刻」「終了済」のみ。同一幅の半透明背景（55%）、名称を重複表示しない。
- 瞬間イベントはマーカー、連続現象は区間、予報の不確実性は帯、気象量や潮位等はグラフへ拡張。現行3トラック・5イベントは日付によらない固定模式値。
- 再生、停止、日付、時刻、地図・稜線・詳細の同期。製品での可視判定・イベント・照明は同一の計算結果を参照し、描画と数値の食い違いを防ぐ。

## 5. 設定と詳細情報
- 設定内「表示レイヤー」「一般設定」タブ。初期はレイヤー、最後のタブをlocalStorageで記憶。設定内容全体の永続化や端末同期は未実装。端末同期は後回し。
- レイヤーを天体、地形、光・大気、気象、自然現象で分類。標準/朝夕焼け/山岳プリセット。試作対応と未対応のチェックボックスを区別。
- 一般設定は方位目盛り、分割画面ルーペ、リセット。リセットで初期時刻・方向・画角・地上高等を戻す。設定一括初期化やPC分割比のリセットまでは現行コードにない。
- 詳細は選択時刻、太陽高度/方位、画角、観測点緯度経度・標高・地上高、気象/自然現象の情報を整理。未取得/未接続は明示。
- 今日のイベントは2列、約半分の行高、時刻と項目名。項目名自体をボタンにし、独立「移動」ボタンは廃止。タップで該当時刻へ移動し詳細画面を閉じる。
- 探索メニューは入口のみ：構図→日時、被写体→地点、地平線まで沈む地点、朝夕焼け・自然現象。実際の検索入力・結果UIは検索機能が形になってから設計し、先に固定しない。

## 6. 実装・検証の境界
- UI Lab単一HTML（Vanilla JS, Canvas2D, Leaflet）。本体public/app.mjs、core.mjs、index.htmlは今回変更していない。本体の実地形・太陽計算とUI Labの操作を今後統合する。UI Labの擬似地形・天体・日照・雲・イベント・探索は精度評価に用いない。
- 実データ接続部分は地図タイルと観測地点DEM取得コード。標高取得が成功した場合の地平線半径のみ物理近似。ブラウザでのDEM通信、地上高更新、実機表示はこの記録作成時に未確認。
- 履歴：v0.1〜0.7 レイアウト・画角・ルーペ・アニメーション・地平線／v0.8〜0.16 時間軸・日付固定・ジェスチャー／v0.17〜0.19 山名・ヘッド・イベント表示・PC分割・設定外クリック・高度基準線／v0.20 標高・地上高・2列イベント／v0.21 ヘッダー統合・タブ・方位目盛り／v0.22 メニュー上配置／v0.23〜0.24 ロゴ状態表示。
- 報告済みの個別JS構文チェック、日付選択5件、方位目盛り4件は限定的な検証。v0.24はJS構文チェックを実施。全版を通したブラウザ自動操作試験、実機性能測定、アクセシビリティ検証、配信反映は未実施。ユーザーによる個別試用・指摘をもって全操作の受入合格とはしない。
- 統合時の重点テスト：PC/モバイル分割・回転・連続地点移動、地図扇形と稜線方位の一致（座標・符号）、地上高変更の再計算、日付固定と中央線・バーの一致、UTC/JST境界/秒・日付範囲/年境界、重なるタップ/ドラッグ/ピンチ、ルーペとラベル衝突、方位0/360・高仰角、メニュー外クリック・キーボード、DEM欠損/遅延/取消、同一入力で本体と実データ表示の一致。性能・精度の基準は第1〜5回の暫定目標を引き継ぐ。

## 7. 次工程
通常UIの見た目の追加改修は一区切り。細部は実データ統合時に必要なものだけ直す。
1. 第7回：運用費・収益化・公開範囲・開発計画を整理し、実装優先順と採用基準を確定。開発を妨げる不要な設計会議は増やさない。
2. 実地形・天体計算と新UIを統合。共通天球投影、地形面・観測位置・太陽/月の同一座標、欠損処理。旧本体機能を意図せず削除しない。
3. 正確な遮蔽・再出現・日照を検証し、撮影地点・日時の逆探索を実装。地図レイヤー・結果UIを実計算に合わせて設計する。
4. 気象・大気・自然現象と統合し、商用利用条件・許可・費用・信頼度を検証する。
- 実用検証の最初の候補：富山平野から立山連峰を見るケース（2026-11-30の撮影計画と関連）。実際の眺望・光を検証する対象候補であり、当日の天気調査や旅行判断は別の作業。ここでは予報を生成しない。日付までの完成を保証しない。

### 追記：UI Lab v0.25（第7回で発見した不足）
