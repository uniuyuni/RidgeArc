## 1. 製品の目的（ユーザー要件）
地形・天体・光・気象から未来の風景を予測し、その風景に出会う場所と時間を発見する。「この日に何が撮れるか」「この風景を撮るにはいつどこへ」。写真撮影者が楽しめる直感的な可視化であり、専門技術を見せるソフトではない。可視化できる情報が多いこと自体にも楽しさがある（最新のユーザー発言）。表示は独立レイヤー化して操作を複雑にしない。
- G1：固定地点で太陽が山に隠れる、部分遮蔽、完全遮蔽、再出現の時刻。
- G2：複数の稜線・可視地表と真の視直径をもつ天体円盤・軌跡を同じ角度座標で表示。全方位、天頂、画角、日時操作。
- G3：固定観測点で希望の構図になる日時を探索（ダイヤモンド富士等）。
- G4：指定地域で地形に遮られず地平線/水平線まで日没を見届けられる地点を探索。天文日没・基準地平線・海面水平線は区別し、具体的な連続可視条件は仮仕様。
- G5：被写体地点（撮影者位置ではない）を指定し、重なる天体の位置関係に応じて撮影場所・日時を逆算。地図に候補曲線/帯/点。中心、円盤縁、部分遮蔽も扱い、アクセスは初期には利用者が判断。

拡張要件（初期リリース範囲未定）：月相・月視差・パール富士、星空・天の川・光害、被写体の日照・順光斜光逆光・山頂の最初/最後の光、空の明るさと色・薄明、朝夕焼け（雲の高さ/厚さ/分布と太陽からの光路）、一般気象（気温湿度風向風速突風降水雲量視程等）、雲海・霧・露点・放射冷却、大気透明度（黄砂PM2.5エアロゾル水蒸気）、水鏡、潮汐潮位。予報信頼度・欠損・期間を明示。光芒、月光、複合条件等は未採用提案。積雪・季節・アクセス等は今回の確定範囲外。

## 2. ユーザー体験・可視化（合意と候補）
- 既存のシンプルな2D風景（距離による色、地形の重なり）を継承。内部3Dの採否に関係なく、3Dソフトのオービット操作にしない。ドラッグで方向、ホイール/ピンチで画角、観測点は地図ピン、日時変更で構図を維持。山名/標高と稜線輪郭は独立表示。
- PCとスマートフォン。取得済み地域内の観測点ドラッグを含め60fps目標、未取得データ待ちは許容。GPS・方位センサー・オフラインは候補。地図/風景/時間を同期。
- 地図の幾何学的地平線を観測点中心の円で描き、外を少し暗くする（基本機能）。基準高と地球曲率による距離。円外の山頂も見え得るため不可視と断定しない。
- 別オプションで実際の地形可視領域（viewshed）を表示、遮蔽地形を暗くする（性能検証後の追加候補）。不明と不可視、日照影を区別。地平線円の実装を妨げない。
- 動画編集風マルチトラックタイムライン候補：瞬間イベント/継続区間/予報の不確実性帯/気温・潮位等のグラフ。再生ヘッドと地図・風景連動、必要なトラックのみ。日付範囲の軌跡重ねは複雑化の懸念、開始終了日付き単一スライダーが候補（現行機能はまだ削除しない）。
- 基本風景の登録不要・無料体験は課金検討候補。最終価格・無料有料境界・公開範囲は未決定。

## 4. 技術設計の最新判断（すべて暫定、実装未確定）
### 共通基盤
地理的に固定された共有地形、階層LOD/min-max/欠損とソース版。WGS84/JGD、地心ECEF・局所ENU、測地座標倍精度、標高/楕円体高/ジオイドを混同しない。曲率や屈折を二重適用しない。地形面・天体方向・座標時刻・版を描画と解析で共有。描画LODと精密解析LODは別。70km超も必要に応じ扱う。データ不足を透明な空として確定しない。
9責務：GeoTime / TerrainStore / Geometry / Ephemeris / Visibility-Light / Search / Environment / Renderer / UI。Workerで重計算、最新要求優先と取消、版管理。クライアント/PWA/WebGL2が評価候補、WASM/WebGPU/サーバは測定後。マイクロサービス化は不要。
### 地形データ（第2回のメッシュ第一候補を修正）
地理タイル・保存符号化・計算表現・描画メッシュを別々に決定する。基本は圧縮標高格子。局所基準高＋UInt16量子化と予測差分圧縮を第一評価候補。元DEMのcmを保持できる場合は保持、同一cm格子と境界サンプル共有、収まらなければ分割/32bit、欠損独立マスク。Float16絶対標高は精度が高さに依存するので第一候補にしない。CPU/GPUに16bitのまま保持し参照時に復号する案は未検証。差分圧縮とLERC比較、オーバーフロー、境界、メモリ・速度を測る。
等高線（可変標高刻み/制御点）、スプライン、曲面＋残差、適応TINは研究候補。急峻な地形では予備実験で圧縮格子が有利。穴・オーバーハング等の局所完全3Dを扱えるRayHit/LOS契約は維持。DEMに埋まった穴は置換マスクが必要。点群欠落を穴と断定しない。地物・樹木や3Dデータ取得範囲、利用許諾未調査。
### 描画・取得
描画方式は未決定。正則GPUパッチ＋共有インデックス/標高テクスチャ、Geometry Clipmaps、GPU高さ場レイキャスト、専用2D/放射断面、既存エンジン比較。広角投影・天頂・LOD境界・欠損・GPU/CPUの面一致を試験。現行Mercatorは天頂で発散。三角形を保存しない案も含める。スマホの管理予算案CPU64/GPU地形32/描画24MiB、PC128/64/48MiBは未測定でブラウザ全体ではない。通信並列4を初期候補（2/4/8比較）、優先度・キャッシュ・版・再試行・オフライン、GSI商用再配信/キャッシュ/出典の条件を確認。全地域前取得やサーバ必須化は保留。
### 天文・遮蔽
Astronomy Engine第一評価候補、JPL Horizons・SPA等を独立参照。UTCと現地時刻区別、topocentric（特に月視差）、太陽/月の中心/半径/明部、幾何と大気差別。円盤の可視面積、直接光と雲透過を別にする。Horizonは単調な2.5Dの高速経路。一般のRayHit・有限LOS・円盤の方向別判定で特殊3Dにも拡張。短時間再出現/接線の根を落とさない適応区間探索、未解決は明示。
### 逆算（第3回）
G3/G5：目標方向の赤緯から安全な日付候補絞り込み、連続時間で球面角距離/接触を最終検証。太陽赤緯の日変化、月視差、屈折は保守的範囲で処理し、保証できない候補を除外しない。G5は固定被写体からのviewshedを日付間で再利用（直線LOSの相反性、両端高さ同一条件）。逆方向の線/円錐交差は候補生成。被写体LOSと天体可視性別。G4は方向別の一括地形遮蔽走査が高速候補、地域内の太陽位置変化、曲率、円盤、時間窓、範囲外を精密再評価。初期は探索間隔を明示したサンプル方式、狭い解を漏らさない保証なし。候補なしと存在しないを区別。すべて共通最終判定を使用。

### 光学・日照・陰影（第4回）
観測者の天体可視性、被写体LOS、受光点の直射光、観測輝度を独立。受光点からの有限円盤方向別の遮蔽・入射角・透過率を積分し、円盤可視率と直射光量を分ける。直線稜線の円盤面積公式は近似高速経路、斜面接線や複雑稜線は積分。被写体の最初/最後の光は複数日照区間、法線、任意光量閾値、観測者LOSを別記。順光/逆光は被写体基準の観測方向と太陽方向の角度。
地域日照は第3回方向走査を平面・固定方向の高速候補として再利用、地点horizonキャッシュと階層RayHitを併用。任意方向・曲率・屈折・欠損・部分円盤の精密判定は未検証。全セル全方向horizonは保存しない。GPU影は暫定描画用、精密イベントはWorkerの解析経路。地形版・方向・範囲・誤差等をキャッシュ鍵とする。
天空散乱光は余弦重み付き天空率を第一近似、異方性は方向別積分。地表反射・視線透過と光路散乱を分ける。既存距離色と物理量を分け、固定表示露出で時間変化を比較。標準大気/空色LUTは評価候補。水面の反射光路と日照・風波を独立、鏡面幾何から検証。地平線円/地形可視域/日照影は別レイヤー。裸地晴天幾何を検証基線とするが、初期公開範囲は未決定。詳細は [第4回議事録](technical-design-council-04.md)。
 
## 5. 検証記録（第1〜3回の報告値は再実行なし、第4回は新規実行）
- 第4回の合成検証：直線稜線の円盤面積241条件と20000横断面求積の最大絶対差5.342e-8。中心高度0度の水平面では円盤入射積分0.000985184（法線基準）に対し中心角近似0。128×512頂点×10高度の固定+X平面走査655360判定の総当たり相違0、単回3.707 vs 211.706ms。欠損20頂点の離散三値も一致。50km先の250m障害、仰角0.1度では平坦/球面二次近似で判定逆転。再現コード validation/light_reference.py。実地形、任意方向、実機、気象・放射精度は未検証。
- 太陽近似 vs Swiss Ephemeris Moshier：3日/計218サンプル、最大方位誤差0.00928度、幾何高度0.00765度。大気差・実JS・接触は未検証。
- 丹沢GML 2m密走査 vs 試作：2kmで完全取得295/1440方位、MAE 0.01264度、p95 0.07679、最大0.25867。8kmは50方位のみ。実景や全方位精度ではない。synthetic first-hit 4824件の照合記録あり。
- 圧縮研究：225×150の丹沢山地2区画/人工丘、元135000B。最大誤差0.25mで差分圧縮格子22,417/23,310/4,715B、DCT曲面60,404/60,972/3,578B。等高線由来非拘束TINの問い合わせとメモリは不利だったが、精度不一致・欠損・未最適化。UInt16ランタイム、LERC、境界、実機未測定。
- 逆算：固定赤緯全周の合成4,096方向×14,400位相、候補13件一致、0.0677 vs 33.3058ms。固定方向・平面65,536格子点の遮蔽一括走査、3,107地点が取得範囲内で遮蔽物なし、相違0、0.326 vs 13.575ms。実天体・実地形・任意方位・連続面・地球曲率・実端末は未検証。再現コード validation/reverse_search_reference.py、地形検証 validation/tanzawa_sampling.py。圧縮実験の独立再現コードはリポジトリにない。
- 目標値（達成保証なし）：天体幾何0.02度以内を最低比較基準/改善0.01度、同一面稜線p95 0.05度改善、接触数値差1秒、好条件実測30秒探索的目標。操作p95 16.7ms、入力遅延・メモリ・転送・発熱・精度を測る。初期精度資料のp95 0.1度は過去の基準。Mac M1/Android/可能ならiOS、ブラウザ実測未実施。
- 検証の優先：合成既知解、完全なDEMと独立参照（HORAYZON/GRASS/JPL等）、端末測定、実写の同一座標高さ姿勢画角時刻。現実の誤差と数値誤差を区別。

## 6. 競合・商業化
競合調査の主要比較先TPE Web v4、PlanIt Earth、Inverza、PeakFinder。他にPhotoPills、Sun Surveyor、PlanIt Pro、LightChance/SkyCandy。TPEとPlanItは既に逆算、Inverzaは気象/自然現象統合。独自性や優位は未実証。本人限定試用ではTPE/PlanIt操作が難しい（PlanIt地形有料未試用）、TPEの時間軸とPeakFinderの山名稜線に好感、PeakFinderの3D操作は不評。差別化仮説：シンプル2D直接操作、連続地点移動、精度根拠、G4と長期間G5、風景発見の楽しさ。価格・レビューはcompetitive-research.md時点の限定調査。市場規模、支払意欲、競合の実機比較、商用データ許諾、運用費・価格未決定。
